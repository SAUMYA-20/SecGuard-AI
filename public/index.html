How to Use SecGuard AI

SecGuard AI allows developers, DevSecOps teams, and site owners to instantly evaluate the security posture of any publicly reachable web surface. Auditing a website requires only a few straightforward steps:

Step 1: Enter Target URL

In the top input bar, enter the domain or full URL you wish to audit (for example: https://github.com, cloudflare.com, or your own staging/production app). You can also click any of the Quick Target Presets to run a test audit instantly.

Step 2: Dispatch the Audit

Click the Dispatch Audit 🚀 button. SecGuard immediately initiates asynchronous multi-vector telemetry probes against the target website.

Developer Pro Edition: The platform is completely open and free. There are no sign-up forms, API paywalls, or scan limits.

Live Telemetry Pipeline

When an audit is dispatched, SecGuard executes a 6-stage telemetry probe in real-time:

  1. Job Dispatch: Job is enqueued into the asynchronous broker with retry backoff.
  2. TLS & Certificate Handshake: Inspects the cryptographic handshake, active cipher suite, and certificate expiration.
  3. Cheerio DOM AST Parse: Parses the HTML Document Object Model looking for client-side risks, inline scripts, and unencrypted forms.
  4. Deterministic Scoring Engine: Mathematically computes a 0-100 security score based on verified findings.
  5. Gemini 3.6 DevSecOps Reasoning: Synthesizes detailed threat assessments and tailored code patches for the identified flaws.
  6. Drift Timeline Persistence: Saves the audit snapshot in MongoDB Atlas for historical drift analysis.

Understanding Scores & Grades

SecGuard uses an objective, reproducible 100-point rubric isolated from AI hallucination:

  • Grade A (90 - 100): Robust security posture with all primary transport headers, modern TLS, and zero high-risk client scripts.
  • Grade B (75 - 89): Good baseline with minor missing secondary headers (e.g. Referrer-Policy or Permissions-Policy).
  • Grade C (60 - 74): Moderate risk with missing essential protections such as HSTS or Content-Security-Policy.
  • Grade D (40 - 59): Elevated risk with vulnerable legacy libraries or missing clickjacking defenses.
  • Grade F (Below 40): Critical vulnerabilities detected (e.g. unencrypted form actions, cleartext HTTP, outdated libraries).

How SecGuard Works (Under the Hood)

Unlike basic HTTP header checkers that only execute a single curl request, SecGuard combines network-layer cryptography, AST structural DOM inspection, and Generative AI reasoning:

When you dispatch an audit, SecGuard connects to the target over HTTPS to inspect the TLS socket directly, extracting certificate authorities and cryptographic ciphers. Simultaneously, it fetches and parses the HTML into a Cheerio Abstract Syntax Tree to identify dangerous patterns (such as outdated jQuery 1.x fingerprints or passwords submitting over cleartext HTTP) that headers alone cannot reveal.

Dynamic Gemini 3.6 Reasoning Engine

SecGuard integrates Google Gemini 3.6 as an intelligent reasoning layer on top of the deterministic scan data.

Instead of generic, repetitive advice or dumping arbitrary server configs, Gemini 3.6 generates dynamic, contextual threat assessments and code patches:

  • Executive Threat Assessment: Evaluates attack surface resilience, risk tiers, and compliance impact (OWASP, SOC2).
  • Vulnerability Threat Modeling: Details the exact mechanics, CVSS rating, and blast radius for each discovered flaw.
  • Tailored Code Fixes: Generates exact code snippets only for the issues found (HTML form fixes, script updates, or server header directives).

Cybersecurity Terms & Vulnerability Encyclopedia

Key security vectors evaluated during every analysis:

Content-Security-Policy (CSP)
Restricts what scripts, styles, and media browsers can execute. Essential for stopping Cross-Site Scripting (XSS) and data injection.
Mitigates: Malicious script execution & cookie theft.
Strict-Transport-Security (HSTS)
Instructs browsers to always use encrypted HTTPS, preventing Man-in-the-Middle (MITM) downgrade attacks and SSL stripping.
Mitigates: Eavesdropping & packet sniffing.
X-Frame-Options (Clickjacking)
Prevents a site from being embedded inside transparent iframes on third-party domains, stopping Clickjacking and UI redressing.
Mitigates: Unauthorized user actions & click hijacking.
X-Content-Type-Options: nosniff
Forces browsers to adhere strictly to declared MIME types, preventing non-executable files (like avatars) from running as scripts.
Mitigates: MIME confusion attacks.
Legacy jQuery 1.x/2.x Fingerprints
Older jQuery versions contain known CVE vulnerabilities (such as CVE-2015-9251 and CVE-2020-11022) susceptible to prototype injection.
Mitigates: Client-side XSS via outdated dependencies.
Cleartext HTTP Form Submissions
Forms that submit login credentials, search terms, or tokens over unencrypted HTTP can be intercepted on public Wi-Fi networks.
Mitigates: Plaintext credential interception.
